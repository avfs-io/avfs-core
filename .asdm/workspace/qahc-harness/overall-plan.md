## 概述

AVFS (Agent Virtual File System) 是一个通用跨存储寻址协议 — 为 AI 智能体设计的统一虚拟文件系统，将本地磁盘、HTTP/HTTPS、SMB、Git 仓库统一为 `avfs://` 标准地址，基于 协议规范 v1.0 | CLI 工具、多语言 SDK、驱动插件系统 构建。

### 核心能力

- **统一寻址协议**：将本地文件系统、HTTP/HTTPS 网络资源、SMB 局域网共享、Git 仓库等异构存储统一为 `avfs://` 标准命名空间，AI Agent 通过单一地址即可定位任意来源的文件资源
- **协议-驱动插件架构**：协议标识符（`file`/`http`/`https`/`smb`/`git`/自定义）与访问驱动一对一绑定，通过插件注册表动态调度；内置 5 类驱动，支持第三方自定义协议扩展
- **AI Agent 原生集成**：提供可复用的 SKILL 定义，教导 AI Agent 使用 `avfs` CLI 进行地址识别、双向转换、资源获取和插件管理，用户以自然语言表述意图，Agent 自动翻译为 AVFS 操作
- **双向无损转换**：`avfs://` 地址与原始系统路径/URL 之间可实现无损双向映射（`--to-avfs` / `--to-native`），所有协议均支持
- **二进制流透明传输**：路由层仅负责定位和调度，不修改原始数据；文件内容以原始二进制流传递，兼容全文件格式

## 核心概念：模块与特性

本文档使用**模块**和**特性**两个核心概念来组织项目规划：

| 维度 | 模块（Module） | 特性（Feature） |
|------|----------------|-----------------|
| **定义** | 项目中的功能区域，从业务领域角度进行稳定划分 | 项目研发过程中规划的可交付单元 |
| **稳定性** | 相对稳定，反映业务领域边界 | 持续变化，随研发迭代演进 |
| **生命周期** | 长期存在 | 规划 → 实现 → 交付 → 维护 |
| **关系** | 特性对模块产生变更作用 | 每个特性归属一个或多个模块 |

## 团队协作流程

1. 需求澄清 → 执行 `/qahc-harness-askme` 消除歧义
2. 产品设计 → 执行 `/qahc-harness-design` 输出 PRD
3. 任务规划 → 执行 `/qahc-harness-plan` 输出开发计划
4. 编码实现 → 执行 `/qahc-harness-develop` 自动编码闭环
5. 测试验证 → 执行 `/qahc-harness-testplan` 生成测试计划并验证
6. 验收审查 → 执行 `/qahc-harness-verify` 生成功能验收报告
7. 构建发布 → 执行 `/qahc-harness-deploy`（后续实现）

## 功能模块

| 编号 | 模块名称 | 说明 | 状态 |
|:----:|----------|------|:----:|
| 1 | 地址解析与路由（core/） | `avfs://` URI 语法校验与字段提取、路径规范化、协议匹配与请求分发 | 🔵 规划中 |
| 2 | 凭据管理（core/） | 凭据存储与解析（精确匹配→模式匹配→匿名）、多来源优先级管理、凭据安全路由 | 🔵 规划中 |
| 3 | 插件注册表（core/） | 协议↔驱动映射维护、运行时热插拔注册/注销、协议标识符唯一性检查 | 🔵 规划中 |
| 4 | 驱动层（driver/） | 5 类内置驱动实现（file/http/https/smb/git），统一 Driver 接口契约 | 🔵 规划中 |
| 5 | CLI 工具（cli/） | 命令行交互界面，含 6 组子命令：fetch/convert/stat/validate/plugin/credential | 🔵 规划中 |
| 6 | 多语言 SDK（sdk/） | 面向各语言的集成开发包，封装地址解析、驱动调用和转换能力 | 🔵 规划中 |
| 7 | AI Agent SKILL（skills/） | 可复用 AI 能力包，教导 AI Agent 使用 `avfs` CLI 完成地址识别、双向转换、资源获取和插件管理 | 🔵 规划中 |
| 8 | 协议规范文档（docs/） | 中英文双语协议规范（地址语法、驱动接口、认证凭据、插件生命周期、转换规则） | 🔵 规划中 |
